# Аналіз архітектурних рішень для продажу плагінів

## 1. Порівняння варіантів реалізації продажів та оновлень

### Варіант 1: Інфраструктура «Все в одному» на Freemius
*Хмарне SaaS-рішення «під ключ». Сервіс повністю бере на себе логіку ліцензування, оновлень та податків (діє як Merchant of Record), але надає два різні сценарії для організації вітрини продажів.*

* **Сценарій А: Продажі через сайт (Інтеграція плагіна вітрини).** 
  Компанія створює свій контентний сайт на який встановлюється безкоштовний офіційний плагін *Freemius for WordPress*. На сторінки виводяться динамічні таблиці тарифів (ціни підтягуються з кабінету Freemius). Покупка відбувається у захищеному спливаючому вікні (Checkout Overlay) безпосередньо на нашому сайті, і тут же для клієнта розгортається його особистий кабінет.
* **Сценарій Б: Продажі повністю на ресурсах Freemius (Без власного сайту).** 
  Компанія взагалі не створює свій сайт-магазин. Замість цього використовуються готові сторінки оформлення замовлення (Checkout Pages), які хостяться на серверах Freemius. Посилання на ці сторінки можна розмістити в соціальних мережах, рекламі або вбудувати безпосередньо в інтерфейс безкоштовної версії плагіна в адмінці WordPress користувача. Клієнт купує та отримує ліцензії на домені Freemius, що зводить підтримку нашої веб-інфраструктури до нуля.

* **Як працюють оновлення:** Клієнт бачить стандартне сповіщення в адмінці WP. Оновлення завантажуються з захищеної CDN Freemius. Якщо ліцензія (на 1 сайт) вже активована на іншому домені, система заблокує оновлення та запропонує скинути прив'язку або купити новий ключ. При збірці плагіна для каталогу WP.org робот Freemius автоматично вирізає комерційний код з безкоштовної версії.
* **Фінансова модель:** Без передоплати. Комісія платформи складає **7% – 16,5%** з кожного продажу (відсоток знижується з ростом обсягів).


### Варіант 2: Автономний інтернет-магазин (WooCommerce + Paddle)
*Повністю незалежна e-commerce екосистема на базі власного сайту з використанням шлюзу-посередника для автоматизації податків.*

* **Як працюють продажі:** На вашому сервері розгортається повноцінний магазин WooCommerce. Для прийому платежів та автоматизації світових податків підключається шлюз **Paddle** (через плагін PaddlePress), який також працює як Merchant of Record. Спеціальний плагін (наприклад, *Software License Manager* або *Software License for WooCommerce*) генерує ліцензійні ключі для кожного замовлення.
* **Як працюють оновлення:** До коду плагінів додаються кастомні серверні хуки (`site_transient_update_plugins` та `plugins_api`). Клієнт оновлює плагін в один клік. Його сайт робить запит до бази даних WooCommerce, перевіряючи, чи не прив'язаний цей ключ уже до іншого сайту. Якщо ключ валідний для 1 сайту — сервер віддає тимчасове посилання на скачування `.zip` з нашого хостингу.
* **Фінансова модель:** Фіксовані витрати на купівлю плагінів ліцензування (близько **\$150–\$300/рік**) + комісія Paddle (**5% + \$0.50** з кожної транзакції).

### Варіант 3: Гібридний легкий стек (Lemon Squeezy + GitHub / PUC)
*Сучасний підхід інді-розробників: мінімум інфраструктури, використання готового віджета продажів та хмарного репозиторію.*

* **Як працюють продажі:** Продажі йдуть через платіжний віджет **Lemon Squeezy** (працює як Merchant of Record, закриває питання податків), який можна вбудувати на будь-який простий лендінг. Сервіс сам генерує ключі та має вбудоване API для обмеження активацій (перевіряє ліміт на 1 сайт).
* **Як працюють оновлення:** У код плагіна інтегрується безкоштовна open-source бібліотека **Plugin Update Checker (PUC)**. Файлы нових версій зберігаються у приватному репозиторії GitHub. Розробник пише невеликий скрипт-прослойку (мікросервіс) на своєму сервері. Запит на оновлення від клієнта йде на цей скрипт, той через API Lemon Squeezy перевіряє ліцензію, і якщо все добре — проксіює файл оновлення з GitHub API клієнту.
* **Фінансова модель:** Без передоплати. Комісія Lemon Squeezy: **5% + \$0.50** за транзакцію.

### Важливе застереження щодо Варіанту 3 (Lemon Squeezy)

При розгляді платформи Lemon Squeezy необхідно враховувати два критичні фактори — технічний та юридично-комплаєнсний:

1. **Наявність офіційного плагіна для сайту:**
   Lemon Squeezy, аналогічно до Freemius, має офіційний безкоштовний плагін для WordPress (*Lemon Squeezy for WordPress*). Його можна встановити на наш сайт для організації вітрини. Плагін підтримує готові блоки Гутенберга, дозволяє легко виводити таблиці тарифів та запускати фірмове спливаюче вікно оплати (Checkout Overlay) прямо на нашому домені, позбавляючи потреби будувати складну кошикову систему на WooCommerce.

2. **Обмеження для резидентів України (Критичний ризик):**
   На сьогодні Lemon Squeezy **офіційно не підтримує реєстрацію нових акаунтів для фізичних осіб та компаній, які є резидентами України**. Це пов'язано з внутрішньою політикою відповідності (compliance) платформи та обмеженнями їхніх базових платіжних провайдерів (зокрема Stripe).
   * **Рішення для бізнесу:** Використання цього варіанту можливе лише в тому випадку, якщо компанія вже має (або планує відкрити) юридичну особу та банківський рахунок за кордоном — наприклад, у США (через Stripe Atlas) або в одній із країн Європейського Союзу.

## 2. Порівняльний аналіз варіантів за ключовими критеріями

### Складність та швидкість розробки
* **Варіант 1 (Freemius):** Низька складність. Запуск займає **2–5 днів**, оскільки використовується готове SDK.
* **Варіант 2 (WooCommerce + Paddle):** Середня складність. Запуск займає **2–3 тижні** через необхідність налаштування та тестування зв'язки плагінів на власному сайті.
* **Варіант 3 (Lemon Squeezy + GitHub):** Вище середньої. Запуск займає **3–5 днів**, але вимагає від розробника написання кастомного коду для мікросервісу-валідатора.

### Технічне навантаження на наш сервер
* **Варіант 1 (Freemius):** Нульове. Усі запити клієнтів на оновлення та перевірку ліцензій обробляються через хмарну CDN-мережу платформи.
* **Варіант 2 (WooCommerce + Paddle):** Високе. Кожен клієнтський сайт буде щодня надсилати запити на наш сервер, що вимагає оптимізації бази даних та кешування (Redis/Memcached).
* **Варіант 3 (Lemon Squeezy + GitHub):** Нульове. Навантаження з роздачі важких файлів оновлень повністю перекладається на сервери GitHub.

### Адміністрування та контроль даних
* **Варіант 1 (Freemius):** Обслуговування сервера не потрібне, але контроль над клієнтською базою частково обмежений екосистемою платформи.
* **Варіант 2 (WooCommerce + Paddle):** Потребує регулярного адміністрування (налаштування безпеки власної БД, створення бэкапів магазину), проте забезпечує 100% контроль над даними.
* **Варіант 3 (Lemon Squeezy + GitHub):** Мінімальне обслуговування, оскільки потрібно підтримувати лише сторінку продажів.

### Фінансова вигода та світові податки
* **Варіант 1 (Freemius):** Повністю закриває питання світових податків (НДС/VAT), але бере найвищу комісію (**7% – 16,5%**).
* **Варіант 2 (WooCommerce + Paddle):** Автоматично вирішує питання податків через Paddle із мінімальною комісією (**5% + $0.50**), але вимагає щорічних витрат на ліцензійні модулі (~$150–$300/рік).
* **Варіант 3 (Lemon Squeezy + GitHub):** Повністю закриває питання податків із вигідною комісією (**5% + $0.50**) та без фіксованих щорічних витрат.

## 3. Рекомендації щодо просування плагінів залежно від обраної реалізації

Маркетингова стратегія та ефективність залучення користувачів будуть суттєво відрізнятися залежно від того, яку інфраструктуру обере компанія. 

### При виборі Варіанту 1 (Freemius)

#### Маркетинг для Сценарію А (Інтеграція плагіна вітрини на нашому сайті)
* **Класичне контентне SEO та брендінг:** Оскільки продажі відбуваються на нашому домені, необхідно оптимізувати сайт під пошукові запити (SEO). Створення якісної документації, блогу з розв'язанням проблем користувачів та сторінок порівняння з конкурентами дозволить залучати безкоштовний органічний трафік із Google безпосередньо на сторінку з плагіном вітрини Freemius.
* **Ретаргетинг та веб-аналітика:** Наявність власного сайту дозволяє встановити пікселі відстеження (Meta, Google Tag Manager). Ви зможете запускати рекламу на тих користувачів, які зайшли на сайт, вивчали таблицю тарифів через плагін Freemius, але з якихось причин не завершили покупку.

#### Маркетинг для Сценарію Б (Продажі повністю на ресурсах Freemius)
* **Агресивний In-Dashboard маркетинг (Продажі всередині WP):** Оскільки власного сайту немає, основним джерелом клієнтів стає каталог WordPress.org. Маркетинг повністю переноситься всередину безкоштовної версії плагіна. Необхідно налаштувати інтерактивні підказки та заблоковані кнопки PRO-функцій в адмінці користувача, які при натисканні одразу відкривають платіжну сторінку на серверах Freemius.
* **Кампанії покинутих кошиків та робота з базою:** Оскільки Freemius автоматично збирає емейли користувачів (навіть безкоштовних версій) та фіксує переходи на свої платіжні сторінки, основний фокус просування зміщується на email-маркетинг. Платформа сама надсилатиме серію тригерних листів із нагадуваннями або купонами на знижку тим, хто закрив сторінку оплати на її ресурсах.


### При виборі Варіанту 2 (WooCommerce + Paddle)

* **SEO та контент-платформа:** Оскільки продажі відбуваються на вашому власному сайті, необхідно інвестувати в його просування. Потрібно створити блог із вирішенням технічних проблем користувачів, документацію та базу знань. Це залучатиме органічний Google-трафік в обхід каталогу WordPress.org.
* **Власна реферальна / партнерська програма (Affiliate Marketing):** За допомогою додаткових плагінів для WooCommerce (наприклад, *AffiliateWP*) можна запустити власну партнерську мережу. Ви зможете залучати блогерів, оглядачів та WP-агентства, виплачуючи їм відсоток за кожного приведеного покупця. У Варіанті 1 це робити значно складніше та дорожче.

### При виборі Варіанту 3 (Lemon Squeezy + GitHub)

* **Маркетинг для розробників та агенцій (Indie Hacker style):** Цей стек ідеально сприймається професійною спільнотою. Ефективно працює стратегія «Building in public» (публічна розробка): демонстрація процесу створення, релізи на Product Hunt, активність у Twitter/X та тематичних Reddit-спільнотах.
* **Гнучкі промо-кампанії та інфлюенс-маркетинг:** Lemon Squeezy дозволяє миттєво генерувати посилання на знижки та створювати унікальні цінові пропозиції для конкретних лідерів думок (наприклад, іменний купон для відомого YouTube-блогера, який робить огляд на ваш плагін).

## 4. Захист PRO-коду від піратства та створення Nulled-версій

Оскільки плагіни WordPress розповсюджуються з відкритим вихідним кодом (PHP є інтерпретованою мовою), будь-який клієнт із PRO-ліцензією теоретично має повний доступ до платного коду. Завдання розробника — максимально ускладнити несанкціоноване копіювання продукту та обхід ліцензійної перевірки.

### Варіант 1: Захист в екосистемі Freemius
*Рівень захисту: Середній / Автоматизований*

* **Як влаштовано захист:** Freemius використовує власне SDK, яке періодично виконує зашифровані асинхронні запити до своїх серверів для перевірки статусу домену. 
* **Технічні особливості:** Скрипти перевірки частково обфусковані (заплутані) всередині самого SDK. Якщо хакер спробує просто вирізати перевірку ліцензії, плагін перестане працювати, оскільки багато PRO-функцій викликаються через специфічні закриті класи Freemius.
* **Аналітика піратства:** У панелі розробника ви будете бачити «аномальні» активації (наприклад, якщо один ключ використовується занадто часто або якщо плагін працює на підозрілих доменах).

### Варіант 2: Захист при власному рішенні (WooCommerce + Paddle)
*Рівень захисту: Повністю контрольований розробником*

У цьому сценарії захист повністю лягає на плечі нашого програміста. Рекомендується впровадити три рівні захисту:

1. **Серверна залежність (Найефективніший метод):**
   Частину критично важливої або важкої логіки плагіна (наприклад, складна аналітика, генерація важких звітів або робота з зовнішніми API) не потрібно включати в `.zip` плагіна. Вона має виконуватися на нашому центральному сервері компанії. Платний плагін клієнта лише надсилає туди дані та отримує результат. Без активного ключа ліцензії наш сервер просто відмовить у доступі, і «нулед» версія стане марною.
2. **Обфускація PHP-коду:**
   Критичні файли, які відповідають за ліцензування та PRO-функції, можна пропустити через спеціальні енкодери (наприклад, [IonCube Decoder](https://ioncube.com "ionCube PHP Encoder") або безкоштовні аналоги). Вони перетворюють читабельний PHP-код на зашифрований бінарний файл.
   *Мінус:* Це вимагає наявності спеціального розширення на сервері клієнта, що може ускладнити UX для нетехнічних користувачів.
3. **Локальна перевірка та «пастки» (Hooks & Transients):**
   Розробник налаштовує перевірку ліцензії не при кожному завантаженні сторінки (це покладе сервер), а записує статус у `transients` (тимчасовий кеш WordPress) на випадкову кількість годин (наприклад, від 12 до 36 годин). Хакерам важче відстежити такий плаваючий тригер перевірки.

### Варіант 3: Захист у зв'язці Lemon Squeezy + GitHub / PUC
*Рівень захисту: Вище середнього (Хмарна валідація)*

* **Як влаштовано захист:** Оскільки Lemon Squeezy надає потужне та швидке API для перевірки ліцензій, наш мікросервіс-прослойка грає ключову роль.
* **Технічні особливості:** Скрипт-валідатор на нашому сервері може відстежувати IP-адреси, з яких клієнтські плагіни звертаються за оновленнями чи перевіркою. Якщо один і той самий ключ протягом години робить запити з 50 різних IP-адрес, наш мікросервіс автоматично блокує цей ключ у базі Lemon Squeezy за підозру в «зливі» на піратські форуми.

### Юридичний нюанс просування: Ліцензія GPL
WordPress працює під ліцензією **GPL**. За її правилами, будь-який код, який інтегрується в WordPress (включаючи ваші плагіни), автоматично стає похідним і має наслідувати ліцензію GPL. 
* Це означає, що перепродаж або безкоштовне поширення вашого PHP-коду на сторонніх «складчинах» є юридично легальним у світі WordPress.
* **Висновок:** Боротися з піратством суто через заборону копіювання коду в WP — неефективно. Головний фокус просування та захисту має бути на **наданні цінності, яку неможливо скопіювати**: хмарні функції (Варіант 2.1), регулярні автоматичні оновлення безпеки та якісна VIP-підтримка, які доступні лише офіційним покупцям.
