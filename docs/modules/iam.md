# Модуль IAM (Identity & Access Management)

## 1. Загальний опис модуля
Модуль відповідає за автентифікацію користувачів, безпеку сесій, ізоляцію контурів системи та ручне керування доступами з боку Керівництва. Доступ до системи здійснюється виключно за парою `Логін / Пароль`.

---

## 2. Структура каталогів модуля (DDD-lite)

```text
app/Modules/IAM/
├── Controllers/
│   ├── BaseController.php     # Базовий клас модуля, містить глобальні атрибути OpenAPI
│   ├── AuthController.php     # Автентифікація (login, logout, me)
│   └── UserController.php     # Повний CRUD управління користувачами та ролями для Admin
├── Database/
│   └── Seeders/
│       └── IAMDatabaseSeeder.php # Наповнення БД користувачами під всі ролі
├── Providers/
│   └── IAMServiceProvider.php # Реєстрація модуля та його маршрутів у ядрі Laravel
├── Requests/
│   ├── LoginRequest.php       # Валідація входу (email, password)
│   ├── UserStoreRequest.php   # Сувора валідація створення нового користувача
│   └── UserUpdateRequest.php  # Валідація редагування з виключенням поточного ID юзера
└── Routes/
    └── api.php                # Ізольовані маршрути автентифікації та адмін-кабінету
```

## 3. Матриця ролей та Рольова модель (RBAC)

Права доступу розділені на три ізольовані контури за допомогою пакету `Spatie Laravel-Permission`. Призначення ролей та переведення користувачів між ними здійснюється **вручну Адміністратором (Керівництвом)**.

*   **Адміністратор (Керівництво):** Повний безлімітний доступ до всіх контурів системи.
*   **Project Manager (PM):** Керування проєктами, бріфами та тікетами. Без доступу до налаштувань IAM.
*   **Лінійний спеціаліст (Персонал):** Доступ до профільної Бази знань (Onboarding) та створення внутрішніх тікетів.
*   **Кандидат (Стажер):** Доступ виключно до свого покрокового курсу навчання.
*   **Клієнт-Власник:** Доступ тільки до свого конкретного проєкту (`project_id`), заповнення брифу та підписання договору.

## 4. Технічна реалізація сесій та безпеки (Laravel Sanctum)

### 4.1. Кастомний Middleware-захист контурів (`CheckRole`)
Для ізоляції контурів використовується кастомне Middleware `app/Http/Middleware/CheckRole.php`, зареєстроване під аліасом `role`.
*   При спробі доступу до чужого контуру, Middleware блокує запит і повертає стандартизований JSON із HTTP-статусом `403 Forbidden`.

### 4.2. Глобальне перехоплення анонімних запитів (Zero-Redirect API)
Оскільки система є чистим Headless API, в ядрі `bootstrap/app.php` повністю вимкнено стандартний веб-механізм редиректів на сторінку `route('login')`.
*   Правило `redirectGuestsTo(fn () => null)` та метод `shouldRenderJsonWhen()` примусово повертають `AuthenticationException` у форматі JSON із HTTP-статусом `401 Unauthorized` для будь-кових помилок на префікс маршрутів `api/*`.

## 5. Специфікація API-ендпоінтів модулю

### Група А: Автентифікація та сесії (Тег: `Автентифікація`)
*   `POST /api/v1/auth/login` — Авторизація користувача (вхід). Приймає `email` та `password`. Повертає Bearer токен.
*   `POST /api/v1/auth/logout` — Завершення сесії (вихід). Анулює поточний токен Sanctum. Захищено `auth:sanctum`.
*   `GET /api/v1/auth/me` — Отримання профілю поточного юзера, включаючи його роль `roles: ["pm"]` та об'єкт `profile_data`. Захищено `auth:sanctum`.

### Група Б: Адміністрування та CRUD (Тег: `Управління користувачами`)
Усі ендпоінти цієї групи доступні **виключно** для користувачів із роллю `admin` (захищено `middleware('role:admin')`).

*   `GET /api/v1/iam/roles` — Отримання списку всіх ролей та їх базових пермішенів.
*   `GET /api/v1/iam/users` — Список усіх користувачів системи з можливістю фільтрації за роллю (наприклад, `?role=candidate`).
*   `GET /api/v1/iam/users/{id}` — Детальна інформація про конкретного користувача за його ID.
*   `POST /api/v1/iam/users/store` — Ручне створення нового користувача. Приймає `name`, `email`, `password`, `role` та початковий масив `profile_data`.
*   `PUT /api/v1/iam/users/{id}/update` — Універсальне редагування будь-яких текстових полів, пароля (якщо передано), зміна ролі користувача, а також модифікація внутрішніх ключів у JSONB-об'єкті `profile_data`.
*   `DELETE /api/v1/iam/users/{id}` — Видалення користувача із системи за його ID. Доступно тільки для ролі `admin`.
