# Модуль ClientEnvironment (Контур №2: Клієнтське середовище та Документообіг)

## 1. Загальний опис модуля
Модуль забезпечує безпечний, ізольований та мультипроєктний простір для взаємодії з замовником. Він автоматизує збір вимог через динамічний покроковий бриф (паттерн Schema-Data), дозволяє підписувати договори та акти в один клік із фіксацією цифрового SHA-256 сліду, а також ізолює лінійних спеціалістів від прямого контакту з клієнтом за допомогою системи двосторонньої модерації повідомлень у тікетах.

## 3. Матриця Ролей та Захист маршрутів (`CheckRole`)

Доступ до ендпоінтів контролюється за допомогою кастомного Middleware `role` (`App\Http\Middleware\CheckRole`), який підтримує мультиролі (`...$roles`).
*   **Панель управління та модерації:** Доступно строго для ролей `admin, pm`.
*   **Кабінет клієнта:** Доступно для ролей `admin, client`. Роль `admin` (Керівництво) має повний безлімітний доступ та право на повне видалення проєктів/брифів (PM-у видалення заблоковано на рівні методів).

## 4. Бізнес-правила та Безпека (`Project Boundary`)

1.  **Ієрархія Проєктів:** Головний контракт (`parent_id = null`) об'єднує під собою дочірні виробничі етапи (Дизайн, Розробка, SEO) для підтримки мультипроєктності одного замовника.
2.  **Project Boundary:** Клієнт при запитах передає в URL `{project_id}`. Бекенд примусово перевіряє право власності через SQL-фільтр: `where('client_id', auth()->id())`. Будь-яка спроба підміни ID повертає `403 Forbidden`.
3.  **Двостороння комунікація та модерація тікетів:** Пряме спілкування спеціаліста і клієнта заблоковано. Тікети мають жорсткі категорії (`tech_issue`, `documents`, `edits`). Сирий текст від розробників зберігається у `message_from_specialist`. PM виступає фільтром, затверджуючи або пишучи самостійні відповіді у полі `message_to_client`, яке є єдиним видимим вікном для кабінету клієнта. Також PM може самостійно ініціювати тікет для замовника.
4.  **Цифровий підпис:** При кліку на підписання бекенд збирає snapshot проєкту, реквізитів та відповідей брифу, генерує незмінний хеш `SHA-256`, фіксує IP-адресу та User-Agent замовника.

## 5. Специфікація API-ендпоінтів та Інтеграція зі Swagger (Sanctum)

Усі захищені ендпоінти вимагають передачі Bearer токена у схемі авторизації `security: [['sanctum' => []]]`.

### Вкладка 1: Панель Менеджера / Клієнтський Контур
*   `GET /api/v1/client-env/projects` — Дерево усіх проєктів студії (`with('children')`).
*   `POST /api/v1/client-env/projects/store` — Створення картки глобального контракту або дочірнього етапу.
*   `PUT /api/v1/client-env/projects/{id}/update` — Повне редагування всіх полів, зв'язків та відповідей брифу проєкту.
*   `PATCH /api/v1/client-env/projects/{id}/status` — Зміна виробничого статусу контракту/етапу.
*   `DELETE /api/v1/client-env/projects/{id}` — Безповоротне видалення картки проєкту (Дозволено строго для `admin`).
*   `GET /api/v1/client-env/brief-templates` — Список усіх доступних бриф-шаблонів системного конструктора.
*   `POST /api/v1/client-env/brief-templates/store` — Створення нового шаблону брифу з нуля.
*   `PUT /api/v1/client-env/brief-templates/{id}/update` — Повне перезаписування назви та всієї JSONB-структури полів брифу.
*   `PATCH /api/v1/client-env/brief-templates/{id}/fields` — Точкове додавання/видалення конкретного об'єкта поля у схемі.
*   `DELETE /api/v1/client-env/brief-templates/{id}` — Видалення шаблону брифу із СУБД-захистом `onRestrictDelete` (Тільки для `admin`).

### Вкладка 2: Панель Ментора / Модерація Тікетів
*   `GET /api/v1/pm/tickets/moderation` — Список тікетів, що очікують перевірки, з фільтрацією за категоріями (`tech_issue`, `documents`, `edits`).
*   `PATCH /api/v1/pm/tickets/{id}/approve` — Схвалення тікета від спеціаліста, заповнення очищеного тексту `message_to_client` та публікація замовнику.
*   `POST /api/v1/pm/tickets/{id}/reply` — Відповідь PM всередину існуючого тікета клієнта зі зміною статусу на `waiting_client`.
*   `POST /api/v1/pm/tickets/store-for-client` — Створення нового ініціативного тікета менеджером для проєкту клієнта від імені студії.

### Вкладка 3: Кабінет Клієнта / Мультипроєктний Інтерфейс
*   `GET /api/v1/client/projects` — Мультипроєктний дашборд клієнта (для `admin/pm` доступний аудит через `?client_id=X`).
*   `GET /api/v1/client/projects/{id}/brief/template` — Запит структури полів брифу для динамічного рендерингу форми.
*   `POST /api/v1/client/projects/{id}/brief/step` — Порційне збереження відповідей конкретного кроку з динамічною PHP-валідацією.
*   `POST /api/v1/client/projects/{id}/contract/sign` — Фіксація криптографічної згоди з договором та запис мережевого сліду.
*   `GET /api/v1/client/projects/{id}/tickets` — Чат тікетів по проєкту (читання строго відмодерованого поля `message_to_client`).
*   `POST /api/v1/client/projects/{id}/tickets/store` — Створення нового організаційного або технічного тікета з вибором категорії.
